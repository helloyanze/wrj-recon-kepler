# WRJ 算法算例导入与三维飞行动画设计

日期：2026-07-22  
状态：已确认  
默认算例：R10  
数据来源：`data/integration-validation/`

## 1. 目标

将 `integration-validation` 中的算法输出作为任务区域、条带、出动顺序、航迹、高度、速度、油耗和验证状态的唯一业务数据来源，并支持后续通过固定格式 ZIP 在浏览器中导入同结构的新算例。

演示必须完整呈现：

- 全部有效算例，默认打开 R10；
- 算法任务区和侦察条带划分；
- 静态三维规划航迹和动态三维尾迹；
- 按 `plannedLaunchTimeSec` 和 `batchIndex` 执行的 UAV 出动顺序；
- 与算法数据一致的高度、速度、距离、油耗、任务时间和告警；
- 颜色与航迹一致、方向与当前运动方向一致的三角 UAV 标记；
- 后续算例 ZIP 的本地导入、校验、预览、持久化和删除。

本次不增加后端、账号、服务器上传、飞控、实时通信或任务编辑能力。

## 2. 已确认的关键决策

### 2.1 地图坐标表达

算法输出坐标系为 `LOCAL_CARTESIAN_M`，单位为米，没有真实经纬度原点、旋转参数或 EPSG 信息。因此不能宣称算法坐标是真实地理位置。

采用“日月湾视觉锚定”方案：

- 任务区或条带整体中心对齐到固定日月湾视觉锚点；
- 默认解释 `+X` 为东、`+Y` 为北，不额外旋转；
- 使用局部切平面米制换算生成地图绘制经纬度；
- 保留米制距离、方向、相对比例和几何形状；
- 原始 `xM / yM` 始终保留在规范化数据和详情中；
- 页面永久显示“视觉锚定、非真实地理定位”声明。

真实 POI 和真实上下文业务图层默认移除，避免视觉锚定后的算法几何与真实地理对象形成错误关联。卫星或公共地图仅作为视觉背景。

### 2.2 算例范围

构建转换器扫描每个算例的运行结果，为每个算例选择最新的完整可行运行。更新的失败运行不能覆盖或排除较早的最新有效运行。

内置目录包含全部有效算例，R10 为默认算例。R10 是默认验收基准：

- 2 架实体 UAV；
- 5 次出动；
- 3 个执行批次；
- 20 条侦察条带；
- 批次计划起飞时间分别为 `0s`、`1206.801s` 和 `2415.788s`；
- 算法最大高度 `2900m`；
- 算法最大速度 `223.702m/s`。

UI 不写死 UAV 数量、出动次数、批次数或条带数。

### 2.3 转换架构

采用共享纯转换核心：

- Node 脚本用于扫描仓库内算法输出并生成内置算例目录；
- 浏览器 Web Worker 用于解压并转换用户上传 ZIP；
- 两条路径使用相同的输入校验、坐标转换、动画构建和规范化逻辑；
- UI 和 Kepler 加载器只消费稳定的 `CaseBundleV2`，不直接依赖原始算法目录结构。

这样可以避免构建期与运行时转换产生不一致，也把未来算法格式适配限制在转换层。

## 3. ZIP 输入契约

### 3.1 文件发现

一个 ZIP 表示一个算法算例，可以保留原始多层目录结构。解析器递归查找文件：

- `mission_plan.json`：必需，且必须恰好一个；
- `region_profile.json`：可选，用于原始任务区边界；
- `validation_report.json`：可选，用于补充验证信息和一致性复核；
- `score_report.json`：可选，用于补充评分信息和一致性复核；
- `trajectories.geojson`：可选，只用于一致性复核。

找到零个或多个 `mission_plan.json` 均拒绝导入。一个 ZIP 不支持多个算例。

### 3.2 权威性

`mission_plan.json` 是唯一权威数据源，决定：

- `caseId` 和 `planId`；
- assignment、实体 UAV、base、flight candidate；
- `batchIndex` 和 `plannedLaunchTimeSec`；
- 条带编号和分配范围；
- 全部轨迹分段及其几何；
- 高度、速度、持续时间、距离和油耗；
- 覆盖率、makespan、总距离、总油耗、可行性和失败码。

可选文件不能覆盖 `mission_plan.json`，只用于补充任务边界、详细告警和交叉检查。

当 `region_profile.json` 缺失时，转换器根据条带 coverage polygon 生成推导边界，并在数据和 UI 中标注 `DERIVED_FROM_STRIPS`。

### 3.3 有效性

可导入算例必须满足：

- `feasible === true`；
- 至少一个 assignment、一个有效 trajectory 和一个 strip；
- 坐标、时间、时长、高度、速度、距离和油耗均为有限数值；
- 任务时间单调不倒退；
- assignment、trajectory、strip、UAV 和 flight candidate 引用可对应；
- 分段类型和几何足以构建完整动画。

WARNING 允许导入并展示。结构错误、不可行计划、时间倒退或损坏引用拒绝导入。未来未识别格式不做猜测性兼容，错误应包含文件名、字段路径和原因。

## 4. 规范化数据契约

共享转换器输出版本化 `CaseBundleV2`：

```ts
interface CaseBundleV2 {
  version: 2;
  case: CaseIdentity;
  assignments: NormalizedAssignment[];
  sorties: NormalizedSortie[];
  strips: NormalizedStrip[];
  region: NormalizedRegion;
  animation: AnimationBundle;
  metrics: CaseMetrics;
  validation: NormalizedValidation;
  displayTransform: DisplayTransform;
  provenance: ImportProvenance;
}
```

关键语义：

- `uavId` 表示实体 UAV；
- `assignmentId` 表示一次出动；同一实体 UAV 可以顺序执行多次出动；
- `sorties` 保留全部算法分段、原始本地坐标及三维点；
- `strips` 包含条带中心线、coverage polygon、索引、宽度及 assignment/UAV 归属；
- `animation` 包含 Trip 四维路径、分段时间索引、航向计算所需数据；
- `displayTransform` 记录视觉锚点、原始中心、轴向和高度比例；
- `provenance` 记录源路径或 ZIP 名、导入时间、运行时间和源文件摘要哈希。

内置和导入算例使用同一接口。

## 5. 动画和执行顺序

### 5.1 全局任务时钟

动画由全局任务时钟驱动，时间范围为 `0` 到 `missionMakespanSec`。

- assignment 在自身 `plannedLaunchTimeSec` 到达时出现；
- 相同批次和相同起飞时间的出动同时开始；
- 后续批次在各自计划时间开始；
- 同一实体 UAV 的不同 assignment 保持独立状态，但不得被错误地同时激活；
- 切换算例时任务时钟重置；
- 调整图层、打开抽屉或折叠侧栏不重置任务时钟。

控制条提供播放、暂停、拖动和 `1× / 10× / 30× / 60×` 播放倍率。倍率只改变演示推进速度，算法速度和任务时间数值不变。

### 5.2 分段还原

必须保留并播放：

- `TAKEOFF`
- `CLIMB`
- `ENTRY`
- `COVERAGE_LINE`
- `TURN`
- `RETURN`
- `DESCENT`
- `LANDING`

多点分段按几何累计距离分配该分段持续时间，确保 TURN 经过原始弧线所有点。

零水平距离的 CLIMB/DESCENT 使用相同二维位置和不同时间/高度构成四维点，按分段起止高度插值。其余分段按算法高度和速度展示。当前速度直接取算法 `speedMps`，不得根据加速后的屏幕位移反算。

### 5.3 三角 UAV

飞机图标替换为本地、可缩放和可着色的 SVG/网格三角形：

- 尖端代表机头；
- 颜色与实体 UAV 在航迹中的颜色一致；
- 使用细白边和轻量光晕确保卫星底图可见；
- 航向由相邻非重合轨迹点计算；
- 零位移、垂直升降或短暂停留保持上一有效航向；
- 起飞前隐藏，飞行中显示，落地后短暂变暗再隐藏；
- 多架同时飞行的 UAV 保持独立位置、航向和状态。

Kepler 3.2.6 继续负责底图、相机、尺寸管理和调试能力；算法任务区、条带、静态三维航迹、动态尾迹和三角标记由注入同一 MapContainer 的 Deck 图层绘制。动态尾迹使用 Deck `TripsLayer`，所有任务图层共用同一任务时钟、颜色定义和高度比例。这样 `1× / 2× / 4×` 可以同步作用于航迹、尾迹和 UAV，而不需要重新注入 Dataset 或重置动画。

## 6. 三维表达

本项目的三维目标是三维航迹与三维飞行对象。底图可以是平面卫星/公共地图；没有 DEM 服务时不宣称地表具有真实山体起伏。

- 默认地图视角约 `pitch: 55`，允许旋转、俯仰和缩放；
- 任务区和侦察条带绘制在海平面；
- 静态规划航迹、动态尾迹和 UAV 标记使用算法真实高度；
- CLIMB/DESCENT 在三维空间表现垂直升降；
- 重置视角应同时容纳任务区和完整高度范围；
- 默认高度比例为 `1×`，严格使用算法高度；
- 提供 `2× / 4×` 仅视觉高度比例；
- 高度比例必须明确显示，Tooltip、详情和统计仍显示算法真实高度。

## 7. 数据驱动 UI

### 7.1 顶栏

顶栏保留：

- 项目名称；
- 内置/导入算例选择器，默认 R10；
- 可行性或告警状态；
- 导入算例；
- 底图切换；
- 高度比例；
- 重置三维视角；
- 任务概览。

### 7.2 图层侧栏

普通模式展示四类算法图层：

1. 算法任务区；
2. 侦察条带；
3. 静态规划航迹；
4. 动态飞行尾迹。

所有图层支持显隐、透明度和颜色。条带、静态航迹和动态尾迹支持宽度调节。UAV 分类色板根据当前算例动态构建，条带按 assignment 对应的实体 UAV 着色。

侧栏下方以实体 UAV 为一级、assignment 为二级显示动态 roster。状态随任务时钟变化：待执行、飞行中、已完成。

### 7.3 动画控制条

地图底部使用紧凑浮动控制条，不恢复已删除的任务流程阶段条。控制条显示任务时间、倍率、进度、当前批次和正在飞行的出动数。

### 7.4 详情抽屉

任务概览显示算法覆盖率、makespan、总距离、总油耗、批次数、出动数、条带数和验证告警。

点击实体 UAV 显示汇总；点击 assignment 显示计划起飞时间、批次、条带、当前阶段、实时高度/速度、距离和油耗。所有值来自 `CaseBundleV2`，不由 UI 重算业务指标。

## 8. 浏览器导入和持久化

导入流程为：

1. 选择或拖放 ZIP；
2. Web Worker 解压；
3. 共享转换核心校验并规范化；
4. 展示 caseId、UAV 数、出动数、批次、条带、任务时长和告警预览；
5. 用户确认；
6. 保存 IndexedDB；
7. 切换到导入算例。

内置算例只读。导入算例可以删除或重新导入。同一 `caseId + planId` 再次导入时提示覆盖，不静默创建重复项。

IndexedDB 不可用时允许当前会话预览，但明确提示刷新后不会保留。失败或取消导入不能破坏当前算例，也不能部分覆盖已有数据。

ZIP 处理应限制压缩体积、解压总体积、文件数量和单文件大小，并拒绝目录穿越路径。

## 9. 错误处理

加载、转换和导入错误统一携带：

- 阶段：解压、发现、解析、校验、转换、持久化或加载；
- 源文件或 ZIP 名；
- JSON/数据字段路径；
- 人类可读原因；
- 可恢复建议。

错误页或导入窗口允许重试/取消。错误不得触发空数据注入，也不得覆盖当前有效地图状态。

## 10. 测试与验收

### 10.1 数据和转换

- 每个算例选择最新完整可行运行；
- ZIP 的零个/多个 `mission_plan.json`、非法 JSON、不可行计划、时间倒退、非有限数值和损坏引用；
- 可选 region 缺失时生成推导边界；
- 本地坐标视觉锚定和米制比例；
- 内置和浏览器转换输出一致；
- 未知版本明确拒绝。

### 10.2 R10 基准

- 2 架实体 UAV、5 次出动、3 个批次、20 条条带；
- 在 `0s`、`1206.801s`、`2415.788s` 启动对应批次；
- 高度达到 `2900m`；
- 速度达到 `223.702m/s`；
- 同批同时开始；
- 实体 UAV 的后续 assignment 不错误重叠。

### 10.3 动画和三维

- 垂直分段二维位置不变、高度随时间变化；
- TURN 完整经过原始多点弧线；
- 三角尖端与飞行方向一致；
- 零位移阶段保持上一航向；
- 静态航迹、动态尾迹和 UAV 使用算法高度；
- `1× / 2× / 4×` 只改变绘制高度；
- 播放、暂停、拖动、倍率和算例切换状态正确。

### 10.4 UI 和持久化

- 动态 UAV/assignment roster；
- 图层显隐、颜色、透明度和宽度；
- 样式变更不重置动画；
- ZIP 预览、导入、覆盖、删除和刷新恢复；
- IndexedDB 失败时会话级降级；
- WARNING 可见但不阻止有效算例；
- 永久视觉锚定免责声明。

在 Chrome/Edge 和 1920×1080、1366×768 下验收全部内置有效算例，并上传一个重新打包的 R10 ZIP。完整播放 R10，核对批次、五次出动、条带、三维高度、速度、快进、拖动、刷新恢复和失败回滚。

## 11. 风险与边界

- 视觉锚定不能替代真实地理配准；未来若提供真实原点、轴向和坐标参考，应新增显式 georeference adapter，而不是修改算法原始坐标。
- 平面公共底图不等于三维地形；DEM 地形服务属于可选扩展。
- 高度视觉夸张必须始终可见且不能污染算法真实值。
- 大型 ZIP 和长时任务需要 Worker、限制和性能预算；不得在 React 渲染循环中逐帧复制完整轨迹数组。
- Kepler MapContainer 与 Deck 算法覆盖层必须共用同一相机；全部 Deck 算法图层必须共用同一任务时钟、图层偏好和 UAV 颜色定义，避免状态分叉。
